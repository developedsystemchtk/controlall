# ระบบยืม-คืนครุภัณฑ์ — โรงพยาบาลสันทราย

ระบบยืม-คืนครุภัณฑ์กลาง (ขอยืม → อนุมัติ → ส่งมอบ → รับคืน, แจ้งซ่อม, ตัดจำหน่าย, QR, รายงาน/Excel)
**Frontend:** `index.html` (หน้าเดียว, โฮสต์บน GitHub Pages) · **Backend:** Supabase (PostgreSQL + RPC)

## โหมดจำลองข้อมูล (สำหรับนำเสนอผู้บริหาร)

หน้าล็อกอินมีปุ่ม **ทดลองโหมดจำลองข้อมูล** → เลือกมุมมอง (ผู้บริหาร/ผู้ดูแลระบบ, เจ้าหน้าที่พัสดุ, ผู้อนุมัติ, พยาบาลผู้ยืม)
- ใช้ข้อมูลสมมติ ~40 รายการ 7 หน่วยงาน มีรายการเกินกำหนด/รออนุมัติ/ซ่อม/ตัดจำหน่ายให้เห็นครบ
- **ไม่เรียกฐานข้อมูลจริงเลย** เก็บในเบราว์เซอร์ (sessionStorage) ลองยืม-อนุมัติ-คืนได้จริงภายในโหมดนี้
- แถบสีเหลืองด้านบนมี เปลี่ยนมุมมอง / รีเซ็ตข้อมูล / ออก — ปิดแท็บแล้วข้อมูลจำลองหาย
- ทดสอบอัตโนมัติยืนยันว่าตลอดโหมดนี้ไม่มี network call (`tests/e2e/e2e_demo.js`)

## รูปแบบวันที่/เวลา

- วันที่ทุกจุดแสดงเป็น **วว/ดด/ปปปป** (เช่น 22/11/2026) เวลาเป็น **24 ชั่วโมง HH:MM** ไม่มี AM/PM — รวมหน้าจอ ช่องเลือกวันที่ เอกสารพิมพ์ และไฟล์ Excel
- ช่องเลือกวันที่ใช้ flatpickr (แสดง วว/ดด/ปปปป แต่ส่งให้ระบบเป็น ISO เหมือนเดิม)
- ปีที่แสดง: หน้าจอเป็น ค.ศ. เอกสารราชการที่พิมพ์เป็น พ.ศ. — เปลี่ยนได้ที่ค่าคงที่ `DATE_BE_UI` / `DATE_BE_DOC` ใน `index.html`

## ติดตั้ง (ครั้งเดียว)

1. เปิด Supabase → **SQL Editor** → วางไฟล์ [`supabase/001_backend.sql`](supabase/001_backend.sql) ทั้งไฟล์ → **Run**
   - ผลลัพธ์สุดท้ายจะแสดง `username = admin` และ **รหัสผ่านเริ่มต้นแบบสุ่ม** (แสดงครั้งเดียว — จดไว้)
   - รันซ้ำได้ ไม่ลบข้อมูลเดิม และไม่สร้างแอดมินซ้ำ
2. ตรวจ `config.js` ว่า `SUPABASE_URL` / `SUPABASE_KEY` (publishable key) เป็นของโปรเจกต์ที่รัน SQL
3. เปิดเว็บ → ล็อกอิน `admin` → เมนู **ผู้ใช้งาน & สิทธิ์** เปลี่ยนรหัสผ่านทันที
4. เมนู **ตั้งค่าระบบ & โลโก้** ใส่ที่อยู่ เบอร์โทร ผู้ลงนาม เลขหนังสือ แล้วเพิ่มหน่วยงาน/ผู้ใช้

> ต้องเปิด **Data API** ของโปรเจกต์ไว้ (ค่าเริ่มต้น) และให้ schema `public` เป็น exposed schema

## สิทธิ์ผู้ใช้ (บังคับที่ฐานข้อมูล ไม่ใช่แค่ซ่อนเมนู)

| Role | ทำได้ |
|---|---|
| SuperAdmin | ทุกอย่าง: หน่วยงาน ผู้ใช้ ตั้งค่า ครุภัณฑ์ทุกหน่วย |
| DeptAdmin | จัดการ/ตัดจำหน่าย/อัปเดตซ่อม **เฉพาะครุภัณฑ์ของหน่วยตนเอง** และอนุมัติ-ส่งมอบ-รับคืนครุภัณฑ์ของหน่วยตน |
| Approver | อนุมัติ/ปฏิเสธ/ส่งมอบ/รับคืน ทุกรายการ ดูรายงาน |
| Borrower | ขอยืม ยกเลิกคำขอของตนเอง แจ้งซ่อม ลงทะเบียนเองได้ (ได้ Role นี้เท่านั้น) |

## ความปลอดภัย

- ตารางทั้งหมดอยู่ใน schema `af` ที่ API เข้าไม่ถึง — หน้าเว็บเรียกได้เฉพาะฟังก์ชัน `rpc_*` (16 ตัว)
- ทุกฟังก์ชันตรวจ **session token** และ Role ที่ฝั่งฐานข้อมูล ไม่เชื่อข้อมูลผู้ใช้ที่ส่งมาจากเบราว์เซอร์
- รหัสผ่าน bcrypt, session เก็บแบบ SHA-256, ล็อกบัญชี 15 นาทีเมื่อใส่ผิด 5 ครั้ง, รหัสผ่านอย่างน้อย 8 ตัว
- รูปภาพ: รับเฉพาะ PNG/JPG/WEBP/GIF ขนาดจำกัด (ไม่รับ SVG) — ย่อขนาดที่เบราว์เซอร์ก่อนส่ง
- `SUPABASE_KEY` ใน `config.js` เป็น publishable key (สาธารณะโดยออกแบบ) **ห้ามใส่ `service_role`/secret key**

## ทดสอบ (เครื่องพัฒนาเท่านั้น)

- `tests/backend_test.sql` — ทดสอบสิทธิ์/ขั้นตอนทั้งหมดบน Postgres (⚠ ล้างข้อมูล: ต้องตั้ง `PGOPTIONS="-c app.allow_test_reset=yes"` และใช้กับฐานข้อมูลทดสอบเท่านั้น)
- `tests/e2e/` — เปิด `index.html` จริงใน jsdom: `node e2e.js` (ต่อ Postgres ในเครื่อง), `node e2e_demo.js` (โหมดจำลอง), `node e2e_dates.js` (รูปแบบวันที่/เวลา), `node sigcheck.js` (ลายเซ็น RPC) — ต้อง `npm i` ก่อน
